# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？

`build.sh` 是脚本，每次运行都会从头到尾执行所有 `gcc` 命令，不管文件有没有改过。Make 的优势是**增量编译**：它读 Makefile 里的依赖关系，通过比较源文件和目标文件的时间戳，只重新编译**被改动的文件**及其依赖目标，没改动的直接跳过。项目大了之后，`build.sh` 全量编译很慢，Make 能省大量时间。




## 2. CMake 是编译器吗？

执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

CMake **不是**编译器。它是**构建系统生成器**，读 `CMakeLists.txt` 后生成底层的构建文件（比如 Makefile 或 ninja 文件），然后由 `make` 或 `ninja` 调用 `gcc` 真正执行编译。最终把 C 源码翻译成机器码的是 **gcc**。


## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

因为编译是 CPU 密集型操作，50 个文件全量重编可能要几分钟甚至更久。实际上只改了一个 `.c` 文件，只需要重新编译那一个文件得到新的 `.o`，再重新链接一次即可，时间从几分钟降到几秒。这也是 Make 和 CMake 存在的主要价值之一。
